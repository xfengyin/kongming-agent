# 推广计划（PROMOTION）— 三国 × 轻量 LLM Agent CLI

> 目标：发布后 6 个月 star ≥ 50（止损 gate）。
> 策略依据：MetaGPT/AutoGPT 已验证「叙事驱动起量」；而本项目的差异化不在规模，
> 而在「极简 + 可读 + 三国叙事」——与重型框架形成对立面。

---

## 一、核心卖点

| 卖点 | 一句话 |
|---|---|
| **极简** | 全项目 ~2500 行、1 个直接依赖（yaml），每个包都能一口气读完 |
| **真实可用** | 一个二进制搞定：对话 / 轻量 RAG / 工具调用 / 会话持久化 / JSON 输出 |
| **真 LLM 实装** | OpenAI 兼容协议一个接口通吃 DeepSeek / 通义 / OpenAI |
| **题材即记忆点** | 你是主公，诸葛亮（LLM）为你运筹帷幄——叙事让每个能力过目不忘 |
| **教学友好** | `pkg/agent` 暴露干净的 `Ask()` 接口，是理解 Agent 编排的最佳最小样本 |
| **零负担体验** | `kongming --mock` 无需 Key 即可离线演示，五秒见真章 |

## 二、目标人群

1. **Go 开发者 / Agent 框架尝鲜者**（主力）：想要「可读、轻量、无黑盒」的 Agent 最小实现。
2. **三国/历史题材爱好者**：被叙事吸引，愿意 star 支持「有趣」的项目。
3. **AI 学习者**：用它入门「对话编排 / Tool Use / RAG 注入 / 多轮历史」的基本形态。
4. **中文技术社区读者**（掘金/知乎）：对「三国 × AI」这种本土化叙事有天然亲切感。

## 四、推广文草稿

### 草稿 1：掘金（技术向）

**标题：2500 行，一个依赖：我用 Go 写了个「诸葛亮」LLM Agent CLI**

> 摘要段（可作开头）：
> 提起 AI Agent，大多数人想到的是 LangChain、AutoGen 这类庞然大物——几百 MB 依赖、
> 层层抽象，新手根本读不完。我做了个相反的尝试：一个纯 Go 的 LLM Agent CLI，
> 全项目 2500 行、只有一个 YAML 依赖，`kongming --mock` 一条命令就能跟诸葛亮聊起来，
> 还内置了轻量 RAG（读本地 .md）、计算器工具、会话保存加载和 JSON 输出。

正文结构建议：
1. 为什么做：重型框架劝退新手，想要一个「能一眼看懂」的最小 Agent。
2. 架构即减法：重构掉 9 个从未接线的死模块，16 包瘦身到 7 包（附删除清单）。
3. 真 LLM 实装：OpenAI 兼容协议一个接口三家厂商；10 行实现自定义 Provider。
4. 能力拆解：多轮历史、RAG 注入、工具短路、会话持久化各一段。
5. 快速上手：`kongming --mock --ask "如何三分天下？"`。
6. 边界与反思：不做什么（向量库/分布式/生产级），为什么限制是优点。

### 草稿 2：知乎（叙事向）

**标题：三国 × AI：用 2500 行 Go 代码，让诸葛亮真正开口说话**

> 摘要段（可作开头）：
> 「运筹帷幄之中，决胜千里之外」——这是诸葛亮，也是我想做的那件事。
> 我写了一个 Go 的 LLM Agent CLI：你是主公，诸葛亮（LLM）回答你的每一个问题；
> 你给它一本知识库（本地 .md），它就真的会去查；你问它「计算 123*456」，
> 它就真的会算。没有 LangChain 的层层抽象，只有 7 个小包、2500 行代码，
> 每个概念都能一眼看懂。

正文结构建议：
1. 从一句诗讲起：为什么「军师」是最合适的 Agent 人格。
2. 演示场景：一问一答 + 多轮对话 + 知识库问答 + 计算器（录屏/截图）。
3. 技术深水区：消息组装、历史透传、工具预检短路、RAG 词频注入。
4. 重构故事：从 16 包 5900 行的「展示架构」砍到 7 包 2500 行的真实产品，
   删除的每个死模块都是踩坑记录。
5. 结尾：开源地址 + 一起把它做成「50 star 的小而美」。
